# Архитектура LocalStudy

## Backend

```text
HTTP request
    |
    v
api/routers + schemas
    |
    v
application/services/{Catalog,Plan,Session,Practice,Analytics}Service
    |
    v
application/ports: CatalogReader, PlanReader/Repository,
                   SessionReader/Repository, PracticeReader/Repository
    ^
    |
infrastructure/repositories/{catalog,plans,sessions,practice}
    |
    v
SQLite / другой SQLAlchemy backend
```

- `src/domain` содержит сущности, статусы и прикладные исключения без FastAPI и
  SQLAlchemy.
- `src/application/services` содержит отдельные сервисы каталога, планов, занятий,
  практики и аналитики. Общий обход зависимостей курсов выделен в `PrerequisiteResolver`.
- `src/application/ports.py` содержит контракты чтения и записи по предметным областям.
  Сервисы аналитики получают интерфейсы чтения; изменения выполняют соответствующие
  репозитории. Для отсутствующих объектов, порядка результатов и атомарности операций
  определены общие правила поведения.
- `src/application/policies` содержит заменяемые алгоритмы расписания, проверки ответов,
  оценки, выбора заданий и рекомендаций. Сервисы получают их через DI. Новое правило
  проверки ответа или рекомендаций добавляется в композицию в `api/dependency_injection`.
- `src/application/schemas.py` содержит DTO результатов. HTTP payload, envelope и
  формат ошибок находятся в `src/api/schemas.py`. Доменные исключения не содержат
  HTTP статусов; их отображение определено в обработчиках API.
- `src/api` отвечает за HTTP, Dishka wiring, конфигурацию, middleware и единый
  формат ошибок.
- `src/infrastructure` содержит модели SQLAlchemy, отдельные repository adapters,
  миграции, seed и собственный JSON-логгер.
- Сессия БД, repository и service имеют request scope; engine и session factory
  — application scope.
- Репозитории сохраняют данные, а расписание рассчитывает `SchedulePolicy`.
  `save_sessions` применяет пакет изменений атомарно. `record_attempt` сохраняет
  попытку и сбрасывает признак подсказки в одной транзакции; при ошибке оба изменения
  откатываются. Баллы и штраф задаёт `ScoringPolicy`.
- Текущее время приходит через `Clock`, что позволяет проверять сценарии с заданной датой.

Авторизация будет добавлена отдельным boundary. Прикладные сервисы не должны
получать или разбирать токены напрямую.

## Frontend

```text
src/
├── app/        # bootstrap, Router, глобальная монохромная тема
├── components/ # локальные исходники компонентов shadcn-vue
├── lib/        # утилиты shadcn-vue
├── pages/      # Plan, Catalog, Sessions, Practice, Analytics
└── shared/
    ├── api/   # типизированные 29 операций и единый HTTP client
    ├── stores/# отдельные stores каталога, плана, занятий, практики, аналитики и сообщений
    ├── services/# интерфейсы API и хранилища, ключи внедрения зависимостей
    ├── storage/# адаптер сохранения снимка плана в браузере
    ├── presentation/# преобразование DTO, дат и ошибок для интерфейса
    ├── types/ # типы представления, независимые от демо-данных
    ├── data/  # явно помеченные демонстрационные данные
    └── ui/    # переиспользуемые UI primitives
```

- Компоненты не вызывают `fetch` напрямую.
- Страницы используют нужные им stores. Stores работают через интерфейсы gateway
  и `PlanStorage`; конкретные HTTP адаптеры и `BrowserPlanStorage` подключаются
  в `app/dependencies.ts`. В тестах они заменяются объектами в памяти.
- Store плана управляет только планом и целями. Занятия, практика и аналитика
  самостоятельно сбрасывают своё состояние при смене плана. `usePlanScope`
  отклоняет запоздавшие ответы от предыдущего плана.
- UI построен на shadcn-vue (Reka UI) и Tailwind CSS 4; компоненты хранятся в
  репозитории и используют только нейтральную чёрно-бело-серую палитру.
- Каждый рабочий экран имеет одно основное действие.
- Расписание в интерфейсе отфильтровывается по идентификатору активного плана.
- Следующее практическое задание запрашивается с `plan_id` и выбирается только из уроков,
  входящих в маршрут плана, включая обязательные курсы-основы.
- `/` перенаправляет на `/plan`.
- На ширине до 760 px sidebar заменяется нижней навигацией, а контент получает
  безопасный нижний отступ.
- Демо-данные никогда не маскируются под серверные: интерфейс показывает
  отдельное уведомление.

## Собственные общие механизмы

- Все успешные ответы имеют envelope `{status, data}`.
- Все ошибки, включая 404/405/422, имеют envelope
  `{status, error: {code, message, details, request_id}}`.
- Request middleware принимает или генерирует `X-Request-ID` и пишет
  структурный JSON-лог стандартными средствами Python.
- Прогресс курса считается по уникальным завершённым урокам и их канонической
  длительности; фактическое учебное время считается отдельно.

## Проверка архитектуры и поведения

- Backend: интеграционные HTTP тесты проверяют 29 операций и формат ответов.
  Общий набор контрактных тестов выполняется для SQLAlchemy и независимых адаптеров
  в памяти. Он проверяет фильтрацию, порядок, отсутствие объектов, изоляцию возвращённых
  данных, обновления, атомарность пакета и однократное использование подсказки.
- Тесты политик проверяют замену алгоритмов без изменения сервисов; отдельный тест
  сбоя записи подтверждает откат попытки вместе с признаком подсказки.
- Frontend: `npm.cmd test` запускает Vitest для stores с подставленными зависимостями,
  сброса данных при смене плана, запоздавших ответов и версионированного хранилища.
